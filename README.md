# MatMulLab — многопоточное умножение матриц на C#

Лабораторная работа № 2 по операционным системам (оценка «4» + юнит-тесты).
Автор: Старков В. А., группа ИТ-6.

Консольная программа на C# (.NET 10) умножает матрицы несколькими потоками и содержит набор бенчмарков, которые показывают, как время и ускорение зависят от числа потоков, порядка циклов, способа передачи данных между процессами и способа распределения строк.

## Возможности

- Умножение обычных матриц `A (n×m) × B (m×k)` вручную созданными потоками (`System.Threading.Thread`, без `Parallel.For` и PLINQ).
- Счётчик прогресса в процентах на атомарной операции `Interlocked.Add`.
- Порядок циклов `i → t → j` (быстрый) и `i → j → t` (школьный), сравнение между собой.
- Генерация матриц в **отдельном процессе**, передача по анонимному каналу (stdout дочернего процесса) в двоичном формате.
- Умножение нижнетреугольной матрицы на обычную: статическое и динамическое (общий счётчик строк) распределение работы.
- Бенчмарки со сбором сырых замеров в CSV и скрипт построения графиков.
- 45 юнит-тестов (xUnit).

## Структура

```
src/MatMul.Core/    матрицы, умножение, прогресс, динамический счётчик строк, формат IPC
src/MatMul.App/     консольная программа: команды mul / tri / bench-* и режим gen (генератор)
tests/MatMul.Tests/ юнит-тесты xUnit

```

## Сборка и тесты

```bash
dotnet build src/MatMul.App -c Release
dotnet test tests/MatMul.Tests -c Release
```

Результат последнего прогона: 45 тестов, 45 успешно, 0 сбоев.

Исполняемый файл — `src/MatMul.App/bin/Release/net10.0/matmul.exe` (на Linux и macOS — `matmul`). Для замеров запускайте именно его, а не `dotnet run`. В примерах ниже он назван `matmul`.

## Использование

```bash
matmul info                                  # логические процессоры, ОС, версия .NET
matmul mul 1000 800 900 4                    # A 1000×800, B 800×900, 4 потока, с прогрессом
matmul mul 1000 1000 1000 4 --verify         # плюс сверка с последовательным умножением
matmul mul 1000 1000 1000 4 --ipc            # матрицы создаёт отдельный процесс
matmul mul 6 6 6 2                           # маленькие матрицы печатаются целиком
matmul tri 2000 2000 8 static                # нижнетреугольная A, статическое распределение
matmul tri 2000 2000 8 dynamic --chunk 8     # динамическое, порция 8 строк
```

## Бенчмарки

Каждая команда пишет сырые замеры в `*_raw.csv` и усреднённые в `*_summary.csv`. Для каждой точки делается 5 замеров, наибольший и наименьший отбрасываются, остальные усредняются.

```bash
matmul bench-mul   --sizes 500,1000,2000 --runs 5 --out mul     # время и ускорение от числа потоков
matmul bench-order --n 2000 --runs 5 --out order                # порядок циклов
matmul bench-tri   --sizes 500,1000,2000 --runs 5 --out tri     # static и dynamic
matmul bench-ipc   --sizes 500,1000,2000 --runs 5 --out ipc     # генерация, передача, умножение
```

Числа потоков: от 1 до числа логических процессоров с шагом 1, затем 1,25·L, 1,5·L, 2·L, 4·L, 8·L. Свои значения: `--threads 1,2,4,8,16`.

Графики:

```bash
python plot.py mul   mul_summary.csv   --physical 10 --logical 16
python plot.py order order_summary.csv
python plot.py tri   tri_summary.csv   --physical 10 --logical 16
python plot.py ipc   ipc_summary.csv
```

## Основные результаты

Умножение, порядок `i → t → j`, время в секундах:

| Потоки | n = 500 | n = 1000 | n = 2000 |
|---|---|---|---|
| 1 | 0,162 | 1,352 | 10,964 |
| 8 | 0,027 | 0,737 | 1,385 |
| 16 | 0,017 | 0,121 | 0,926 |
| 128 | 0,018 | 0,119 | 0,938 |

- **Оптимальное число потоков — 16** (число логических процессоров). Для n = 2000 время падает с 10,96 с до 0,93 с, ускорение около 11,8. После 16 потоков выигрыша нет.
- **До 8 потоков** ускорение почти линейное, дальше растёт медленнее: потоки начинают делить ядра (Hyper-Threading), часть работы достаётся более медленным E-ядрам.
- **Порядок циклов:** `i → t → j` быстрее `i → j → t` в 3,1 раза (10,96 с против 34,09 с при n = 2000), потому что идёт по памяти подряд.
- **IPC:** доля передачи матриц падает с 74 % (n = 500) до 10 % (n = 2000) от общего времени, так как значительная часть передачи — фиксированная стоимость запуска дочернего процесса.
- **Треугольная матрица:** динамическое распределение быстрее статического в 1,4–1,8 раза при T ≤ 16. Ускорение статического хорошо описывается формулой `T² / (2T − 1)`; при T = 128 разница исчезает.

## Ограничения

Часть замеров искажена фоновой нагрузкой на ноутбуке (n = 1000 при 4–8 потоках, начало серий для треугольных матриц), а при малом числе потоков эффективность получилась выше единицы из-за завышенного времени на одном потоке. Подробнее — в отчёте. Многопоточные замеры школьного порядка циклов и разные размеры порции динамического распределения не проводились. Барьер и возведение в степень (задание на «5») не выполнялись.
